# ①디자인 3-B 육안 확인 — 차트 팔레트·다중 계열

> 실시 2026-08-08 · 브랜치 `feat/design-phase3b-charts` · 계획 Task 11
> 도구: `flutter build web --release` + 로컬 정적 서버(`py -m http.server`) + gstack browse 캡처
> 캡처 원본: 세션 스크래치패드(커밋하지 않음)

**왜 하는가:** 3-A에서 위젯 테스트가 전부 green인 상태로 캡처가 결함을 잡았다. 이번에도
**green 상태에서 결함 2건이 나왔다**(§2·§3).

영원히 보이지 않는다**(계획은 "임시로 채운다"고 했으나 성격이 다르다).

## 2. ★결함 1 — 진행 0%인 주차가 화면에서 사라진다★ (수정 완료)

**증상:** 학습 경로의 「주차별 진행률」 카드가 제목과 X축 숫자만 있는 **빈 상자**로 보였다.
막대가 하나도 없다.

**원인:** 경로를 막 만든 사용자는 12주가 전부 0%다. 막대만 그리면 높이 0이라 아무것도 남지
않는다. 목 데이터가 정확히 그 상태였다(`week1`만 과제 3개이고 전부 미완료, 2~12주는 `tasks: []`).
**이것은 목의 특수 상황이 아니라 모든 신규 사용자의 첫 화면이다.**

**위젯 테스트는 green이었다.** `toY: 0`을 정확히 검증하고 있었기 때문이다. 값은 맞는데 화면은
비어 있다 — 3-A에서 세 번 반복된 「테스트가 조건을 비껴간다」와 같은 계열이다.

**수정:** `backDrawRodData`로 배경 트랙(100% `surfaceMuted`)을 깔았다. 도넛이 미완료를 면으로
그리는 것과 같은 원칙이다(스펙 §4). red-repro → 수정 → 재캡처로 확인했다.

## 3. ★결함 2 — 미완료 면이 오히려 덜 보이게 됐다★ (판단 필요, 미수정)

스펙 §4는 도넛 미완료를 `c.border`(경계선 토큰) → `c.surfaceMuted`(면 토큰)로 바꾸라고 했다.
의미론적으로는 옳다. **그런데 실측하면 가시성이 떨어진다.**

| 테마 | `surfaceMuted`(신규) | `border`(기존) | 변화 |
|---|---|---|---|
| 라이트 | **1.14:1** | 1.34:1 | −15% |
| 다크 | **1.08:1** | 1.32:1 | −18% |

(카드 `surface` 대비. 완료 조각 `chart1`은 라이트 6.70:1 · 다크 6.97:1로 문제없다.)

축소 스크린샷에서는 다크 도넛의 미완료 조각이 **보이지 않았고**, 확대해야 겨우 형태가 잡혔다.
주차별 트랙은 면적이 커서 같은 대비에서도 형태로 인지된다.

**판단 근거:** 이 면들은 정보 전달의 주체가 아니라 트랙이다(도넛은 중앙 「62%」 텍스트가,
주차별은 파랑 진행분이 주 정보). WCAG 비텍스트 3:1은 「의미 전달에 필요한」 요소에 적용되므로
위반은 아니다. 그래도 **바꾸기 전이 더 잘 보였다는 사실은 남는다.**

스펙에 명시된 사용자 결정이라 임의로 되돌리지 않았다. 선택지:

- **A. 유지** — 의미론 우선. 트랙은 보조 정보이고 확대하면 보인다
- **B. `border`로 환원** — 가시성 우선, 스펙 §4 철회
- **C. 면 토큰 값 자체를 조정** — `surfaceMuted`는 다른 곳에서도 쓰이므로 파급이 있다

## 5. 캡처 실무 — 이번에 겪은 것

- **`py -m http.server`가 죽으면 아이콘이 □로 깨진 화면이 찍힌다.** 폰트 요청이
  `ERR_EMPTY_RESPONSE`로 실패하는데 화면은 그럴듯하게 렌더된다. **구현 결함으로 오진하기 쉽다.**
  `curl -s -o /dev/null -w '%{http_code}'`로 서버 생존을 먼저 확인하고, `$B console --errors`로
  폰트 fetch 실패를 확인하면 즉시 갈린다(이번에 실제로 오진할 뻔했다).
- **`$B reload`는 앱을 초기 상태로 되돌린다** — 해시 라우트가 유지되지 않아 빈 화면이 된다.
  재확인은 `reload`가 아니라 `goto`로 한다.
- CanvasKit이라 브라우저 스크롤이 없다. 접힌 영역을 보려면 **뷰포트 높이를 키운다**(500x1800).
- 3-A의 「wait --networkidle만으론 이르다」는 이번에도 유효했다. 명시적 5~8초 대기를 썼다.

## 6. 목 데이터의 한계 (테스트로 보완함)

- 목 마일스톤은 12개지만 **전부 0%**라 진행분이 있는 막대를 캡처로 보지 못했다.
  위젯 테스트가 100%/50%/0% 세 케이스를 덮는다.
- 12주 밀집도는 좁은 폭에서 확인이 필요한데 캡처는 1400폭 위주였다.
  `12주 경로를 좁은 폭에서도 오버플로 없이 렌더한다`(360px)로 잠갔다.
