# 축 B: mock OAuth2 provider 웹 로그인 e2e Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`).
> **크로스레포:** 구현=devpath-platform-svc(테스트+의존), 런북 문서=devpath-frontend. 모든 명령에 절대경로/`-C`.

**Goal:** platform 실 Spring Security 필터체인으로 웹 OAuth 로그인 전 흐름(authorize→callback→refresh 쿠키→/auth/refresh→user)을 embedded mock-oauth2-server로 자동 검증한다.

**Architecture:** `@SpringBootTest(RANDOM_PORT)` 테스트가 `MockOAuth2Server`를 띄우고, `@DynamicPropertySource`로 github provider uri를 mock으로 오버라이드한 뒤 리다이렉트 체인을 따라가며 콜백 리다이렉트·refresh 쿠키·/auth/refresh 응답을 단언한다. 실 GitHub은 런북 문서로 분리.

**Tech Stack:** Spring Boot 4.0.7 · Java 21 · spring-boot-starter-oauth2-client · no.nav.security:mock-oauth2-server(embedded).

## Global Constraints

- github provider uri는 Spring 내장 기본값(github.com) → 테스트에서 **provider uri(authorization/token/user-info)를 mock으로 오버라이드**해야 함. `user-name-attribute=id`.
- mock userinfo는 **GitHub 형태 claims** `{id, login, name, email}` 반환. `id`는 DB 충돌 회피용 고유값.
- SuccessHandler는 웹 흐름에서 `{devpath.auth.web-url}/auth/callback`로 302 + refresh HttpOnly 쿠키(`RefreshCookies.COOKIE_NAME`) 설정.
- `/auth/refresh`(웹): refresh 쿠키 → 회전 → `LoginResponse{access_token(비어있지 않음), refresh=null, webCookieMode=true, user:UserSummary{id,email,nickname,role,onboardingStatus}}`.
- 브랜치: platform `feat/oauth-web-e2e`(base develop), frontend는 현재 `docs/oauth-e2e-design`(spec 커밋됨)에 런북 추가.
- 검증: platform `./gradlew build` 그린. CI clean DB. 로컬은 고유 user id로 오염 회피.
- 레포 루트: platform `D:\workspace\dpa\devpath-platform-svc`, frontend `D:\workspace\dpa\devpath-frontend`.

```java
package ai.devpath.platform.auth;

import static org.assertj.core.api.Assertions.assertThat;

import java.util.Map;
import no.nav.security.mock.oauth2.MockOAuth2Server;
import no.nav.security.mock.oauth2.token.DefaultOAuth2TokenCallback;
import org.junit.jupiter.api.AfterAll;
import org.junit.jupiter.api.BeforeAll;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.test.web.client.TestRestTemplate;
import org.springframework.boot.test.web.server.LocalServerPort;
import org.springframework.http.HttpEntity;
import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpMethod;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.test.context.DynamicPropertyRegistry;
import org.springframework.test.context.DynamicPropertySource;

/**
 * 웹 OAuth 로그인 전 흐름 e2e(R4): mock provider로 authorize→callback→refresh 쿠키→
 * /auth/refresh→user를 실 Spring Security 필터체인으로 검증. 실 GitHub은 런북 참조.
 *
 * <p>주의: TestRestTemplate은 302를 자동 추적하지 않도록 리다이렉트를 수동 처리하고
 * (Location + Set-Cookie를 단계별로 이어붙임), state 바인딩용 세션 쿠키를 보존한다.
 */
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class OAuthWebLoginE2ETest {

  static final MockOAuth2Server MOCK = new MockOAuth2Server();
  static final long UNIQUE_GH_ID = 990000001L; // DB 충돌 회피용 고유 id
  static final String WEB_URL = "http://web.test";

  @BeforeAll
  static void startMock() {
    MOCK.start();
    // github provider는 비-OIDC(userinfo 기반). authorize를 비대화형으로 자동 완료시키고
    // userinfo/token claims를 GitHub 형태로 구성.
    MOCK.enqueueCallback(new DefaultOAuth2TokenCallback(
        "github", String.valueOf(UNIQUE_GH_ID), "JWT", java.util.List.of(),
        Map.of(
            "id", UNIQUE_GH_ID,
            "login", "smoke-tester",
            "name", "Smoke Tester",
            "email", "smoke@devpath.test"),
        3600));
  }

  @AfterAll
  static void stopMock() {
    MOCK.shutdown();
  }

  @DynamicPropertySource
  static void oauthProps(DynamicPropertyRegistry r) {
    String issuer = "github";
    r.add("spring.security.oauth2.client.provider.github.authorization-uri",
        () -> MOCK.authorizationEndpointUrl(issuer).toString());
    r.add("spring.security.oauth2.client.provider.github.token-uri",
        () -> MOCK.tokenEndpointUrl(issuer).toString());
    r.add("spring.security.oauth2.client.provider.github.user-info-uri",
        () -> MOCK.userInfoUrl(issuer).toString());
    r.add("spring.security.oauth2.client.provider.github.user-name-attribute", () -> "id");
    r.add("spring.security.oauth2.client.registration.github.client-id", () -> "test-client");
    r.add("spring.security.oauth2.client.registration.github.client-secret", () -> "test-secret");
    r.add("devpath.auth.web-url", () -> WEB_URL);
  }

  @LocalServerPort int port;
  @Autowired TestRestTemplate rest;

  @Test
  void webLoginFlow_redirectsToCallback_setsRefreshCookie_andRefreshReturnsUser() {
    // 리다이렉트 자동 추적 비활성화된 rest 헬퍼로 흐름을 단계별로 따라가며
    // 세션 쿠키(JSESSIONID 등)와 최종 Set-Cookie(refresh)를 수집한다.
    // 1) GET /oauth2/authorization/github → 302 mock authorize (+세션 쿠키)
    // 2) mock authorize 따라가기 → 302 콜백 /login/oauth2/code/github?code&state
    // 3) 콜백 따라가기 → 302 Location = {WEB_URL}/auth/callback + Set-Cookie refresh
    // 4) POST /auth/refresh (refresh 쿠키 동봉) → 200 + access_token + user 일치
    //
    // 구현 주의(라이브러리 상호작용은 실행 시 검증·조정):
    //  - TestRestTemplate 기본은 4xx/5xx에서 예외를 안 던지지만 302는 자동 추적할 수 있으므로,
    //    ClientHttpRequestFactory에 setInstanceFollowRedirects(false)를 준 rest를 쓴다.
    //  - 각 단계의 Set-Cookie를 다음 요청 Cookie 헤더로 누적(세션+refresh).
    //  - mock authorize가 대화형 로그인 페이지를 반환하면 OAuth2Config(interactiveLogin=false)로
    //    자동 완료하도록 MockOAuth2Server 생성 설정을 조정한다(라이브러리 문서 확인).
    var flow = OAuthFlowDriver.run(rest, port, "/oauth2/authorization/github", WEB_URL);

    assertThat(flow.callbackLocation()).isEqualTo(WEB_URL + "/auth/callback");
    assertThat(flow.refreshCookie()).isNotNull();
    assertThat(flow.refreshCookie().toLowerCase()).contains("httponly");

    // /auth/refresh 로 세션 부트스트랩
    HttpHeaders h = new HttpHeaders();
    h.add(HttpHeaders.COOKIE, flow.refreshCookiePair());
    ResponseEntity<Map> res = rest.exchange("http://localhost:" + port + "/auth/refresh",
        HttpMethod.POST, new HttpEntity<>(null, h), Map.class);

    assertThat(res.getStatusCode()).isEqualTo(HttpStatus.OK);
    assertThat(res.getBody().get("access_token")).asString().isNotBlank();
    @SuppressWarnings("unchecked")
    Map<String, Object> user = (Map<String, Object>) res.getBody().get("user");
    assertThat(String.valueOf(user.get("email"))).isEqualTo("smoke@devpath.test");
    assertThat(String.valueOf(user.get("nickname"))).isEqualTo("Smoke Tester");
  }
}
```
그리고 흐름 구동 헬퍼 `OAuthFlowDriver`(같은 파일 하단 static class 또는 별도 test 파일)를 구현한다 — 리다이렉트 비추적 rest로 1~3단계를 따라가 `callbackLocation`·`refreshCookie`(Set-Cookie 원문)·`refreshCookiePair`(name=value)를 담은 record를 반환. **이 헬퍼의 정확한 쿠키/리다이렉트 처리는 실행 시 mock-oauth2-server 동작을 보고 조정한다**(대화형 로그인 여부·code/state 파라미터).
